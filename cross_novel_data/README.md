# Cross-novel 实验输入

本目录是扩展实验专用输入。两个 TXT 都是 UTF-8，不带 BOM。
项目根目录的原始小说和 Task1–4 输出均未修改；扩展实验应使用本目录的两本书，不能把这里的 B 与未经同样处理的原始 A 混用。

## 数据与来源

| 文本 | 文件 | 处理后字符数 |
| --- | --- | ---: |
| A：《权力的游戏》 | `GameOfThrones.txt` | 1,586,146 |
| B：《了不起的盖茨比》 | `TheGreatGatsby.txt` | 266,088 |

- A 来自项目已有的 `../GameOfThrones.txt`，严格按 GB18030 解码；其原文件 SHA-256 记录于 `provenance.json`。
- B 仓库：https://github.com/BlackIQ/the-great-gatsby
- 固定 commit：`cf04165c84a11bc00bbbb9cceef936e0781740ae`
- 固定版本：https://github.com/BlackIQ/the-great-gatsby/tree/cf04165c84a11bc00bbbb9cceef936e0781740ae
- 获取日期：2026-10-11（Asia/Shanghai）。
- 按数字顺序取 `Chapter-1/README.md` 至 `Chapter-9/README.md`，不取 Chapter-0、仓库首页或 HTML。
- `gatsby_source.zip` 保留九章未经修改的源文件，以及仓库的 LICENSE。仓库许可声明不能替代对原作版权状态的判断。
- `provenance.json` 记录各源文件、归档和输出的 SHA-256、逐章长度、字符频数、替换次数及处理规则。

## 一致的预处理规则

1. B 每章去掉最前面的书名 Markdown 标题和加粗的章节标题，再顺序拼接。固定版本的正文无其他 Markdown 格式标记。第九章方括号内的内容属于原文，保留其文字。
2. 对 A、B 均执行 Unicode NFKC 规范化；弯单/双引号转为 ASCII 引号，长短破折号转为 `-`，省略号转为 `...`。
3. 去掉 word joiner、BOM 和分解后的重音符号（例如 é → e、ô → o）。保留英文字母大小写。
4. 将所有换行、制表符、连续空白和 Unicode 空格统一为一个 ASCII 空格，并去掉首尾空白。因此不保留段落边界。
5. 取以上处理后两篇文本实际字符集的交集；不在交集中的字符统一映射为 `?`。`?` 原本就同时存在于两书，不额外注入虚构正文。
6. 保存 UTF-8，无 BOM，不添加末尾换行。

第五步使两篇文本的实际字符集严格相同，共 **72** 种字符。额外替换为：

| 文本 | 替换字符及次数 | 总次数 |
| --- | --- | ---: |
| A | `&`：2；`X`：3 | 5 |
| B | `$`：2；`[`：2；`]`：2 | 6 |

这些是有意记录的有损预处理；后续“无损压缩”针对预处理后的文本。大小写总体保留，但未共同出现的大写 X 在第五步中替换。方括号标点被映射，其内部文字保留。
共同字符集并不保证共同上下文；跨小说建模仍需平滑或回退机制。

## 复现

在项目代码目录执行：

```powershell
python prepare_cross_novel.py
```

只使用 Python 标准库。默认从本目录的来源归档离线重建；归档不存在时，脚本从上述固定 commit 下载九章及 LICENSE。
已有 provenance 时会核对源文件哈希，并保留原获取日期。结果 CSV 或压缩文件应由后续 cross-novel 实验程序生成；本脚本只准备输入。

两篇文本长度约相差 6 倍；后续分析中应区分训练样本量差异与小说风格差异。本文本清理未进行与权威版本的逐字校勘。
