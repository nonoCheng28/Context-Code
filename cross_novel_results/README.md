# Cross-novel 实验说明

## 运行与输出

在项目代码目录运行 `python cross_novel.py`。只依赖 Python 标准库。
默认阶数为 2、3，平滑参数 alpha=0.1；可用 `--orders 2 3 --alpha 0.1` 显式指定。
运行会更新两张 CSV 和 settings.json。本说明对应默认参数。

- `cross_entropy.csv`：guidance 要求的四种建模/测试组合，每阶四行，共八行；附经验条件熵、条件 KL 和未见事件比例。
- `comparisons.csv`：两个方向的额外成本、KL、自模型平滑代价及升阶后的额外成本变化。
- `settings.json`：运行参数、输入哈希、小说标识、B 的来源 commit、脚本哈希和计费口径。

A 是预处理后的《权力的游戏》，B 是预处理后的《了不起的盖茨比》。输入来自 cross_novel_data，运行前核对来源记录中的 SHA-256 和两书的实际字符集。

## 指标与方法

本实验选择 guidance 明确允许的**理论交叉熵**，不是实际 Huffman 压缩文件码率。这样可直接核对概率模型与 KL 的数学关系，不混入整数码长和码表存储开销。

R_AB 的第一个下标表示建模文本，第二个表示测试文本。每阶使用测试文本的位置 i=k,...,N-1，分母 N-k。前 k 个字符、文件头、码表存储和字节补零均不计入理论交叉熵。不要将本表与 Task4 总文件成本作为同一指标比较。

条件概率统一采用加性平滑：

`Q_train(x|c) = (n_train(c,x) + alpha) / (n_train(c) + alpha * 72)`。

未见上下文对应 72 字符上的均匀分布；已见上下文中的未见后继也有正概率。两个诊断列分别统计“未见上下文”与“已见上下文中的未见后继”的测试样本比例，互不重叠。所有四组组合使用相同平滑规则。

令 P_test 为测试文本的未平滑经验条件分布，则：

- `H_test = -sum_c,x P_test(c,x) log2 P_test(x|c)`。
- `R_train,test = -sum_c,x P_test(c,x) log2 Q_train(x|c)`。
- `conditional_KL = sum_c P_test(c) KL(P_test(.|c) || Q_train(.|c))`。
- `R_train,test - H_test = conditional_KL`，程序分别计算两边并验证。
- 自模型也平滑，因此 `R_AB - R_BB = KL_cross_on_B - KL_self_on_B`，不直接等于单个 KL。反方向同理。

两方向的条件 KL 还使用各自测试文本的上下文权重，因此不是固定同一个联合分布后简单交换两个参数；不应仅凭两数不等来证明 KL 的不对称性。

## 默认参数的数值结果（bits/character）

| k | R_BB | R_AB | R_AA | R_BA |
|---:|---:|---:|---:|---:|
| 2 | 2.735453189 | 3.011211952 | 2.683580467 | 3.025419392 |
| 3 | 2.204626044 | 2.695492625 | 2.154231723 | 2.905422716 |

| k | A→B 额外成本 | B→A 额外成本 |
|---:|---:|---:|
| 2 | 0.275758764 | 0.341838925 |
| 3 | 0.490866580 | 0.751190994 |

升阶后额外成本分别增加约 0.215108 和 0.409352 bits/character。与此同时跨小说交叉熵本身下降；“额外成本增加”不等于“跨小说码率上升”。

## 分析边界与验证

自模型是同一本全文建模并评价，不是独立测试集；两篇文本长度约相差 6 倍。观察到的差异同时受文本内容、样本量、阶数和平滑参数影响，不能单独归因于作者风格，也不能把自模型表现作为未见文本泛化能力。
